# 每个功能对应一个价值

> 用法：左边是"我们做了什么"，右边是"所以你该感到厉害的地方"。
> 每一条都带真实数字，**评委可以挑任意一条当场验**。

---

## 一、生成层（4 项）

### 1. 文生视频 · 万相 2.6-t2v · 1080p

| | |
|---|---|
| **功能** | 一句话提示词 → 1920×1080 / 30fps / 5 秒成片 |
| **别人怎么做** | 本地跑，8GB 显存最多 640×384，糊得看不清毛发 |
| **我们做到** | **15 秒出片**，真 1080p，毛发一根根清晰 |
| **价值一句话** | **同样的机器，别人只能出"能看"，我们能出"能播"。** |

---

### 2. 图生视频 · 首帧驱动

| | |
|---|---|
| **功能** | 把选中关键帧作为第一帧，视频从它开始生长 |
| **别人怎么做** | 只做文生视频 → 每一帧都是模型自由发挥，**第 3 秒脸就变了** |
| **我们做到** | 首帧锁定 → 主体一致性从"随机"变成"受控" |
| **价值一句话** | **不是"生成一段视频"，而是"让这张图动起来"——可控性差一个量级。** |

---

### 3. 文生关键帧 · 多候选并出

| | |
|---|---|
| **功能** | 一次出 3–6 张候选图，供后续选优 |
| **别人怎么做** | 出一张，不满意就重抽（抽卡） |
| **我们做到** | 一次 3–6 张，**并给每张打分排序** |
| **价值一句话** | **把"抽卡"变成"选优"——从赌运气变成做选择题。** |

---

### 4. 双引擎切换（H3 / Wan2.2 / 万相）

| | |
|---|---|
| **功能** | 一个界面切三套模型，各自走正确的采样路径 |
| **别人怎么做** | 换模型要重配环境、重调参数，**一处配错整屏噪声** |
| **我们做到** | H3 自动走 `euler/simple + CFG 5–7`，Wan 走 `dpmpp_2m/karras + CFG 7–10`，**平台按引擎自动选** |
| **价值一句话** | **同一套参数喂给不同引擎必崩——我们把这个坑填了，且写进了验收闸（配错直接拒跑）。** |

> 真实案例：我们曾因把 H3 套上 DPM++ 采样器，产出一整屏噪声，而评分器给它打了 0.68 高分。这条 bug 引出了下面第 6 项。

## 二、评估层（4 项）—— **这是全篇最值钱的部分**

### 5. 五维质量打分

| | |
|---|---|
| **功能** | 每张图/每段视频给 5 个分项 + 1 个总分：Sface（主体结构）/ Ssharp（锐度）/ Sstyle（风格匹配）/ Scomp（构图）/ Sbad（退化扣分） |
| **别人怎么做** | 肉眼看，"这张感觉好一点" |
| **我们做到** | **每张候选有 5 个数字 + 1 个总分，可排序、可复跑、可解释** |
| **价值一句话** | **把"我觉得好看"变成"它 0.6553，比另一张高 0.064 分"——评审可以被复核，而不是被说服。** |

---

### 6. 退化检测（三判据）

| | |
|---|---|
| **功能** | 320×180 高频采样，算噪声比 / 边缘密度 / 块方差，任一越界即判退化 |
| **别人怎么做** | 片子"看着不对"但说不出哪不对，只能重跑 |
| **我们做到** | **直接告诉你是哪种坏**：噪声 / 模糊 / 纯色。且退化样本总分被强制压到 0.15 以下 |
| **价值一句话** | **噪声片从 0.6808 被压到 0.1500——不是靠调权重，是靠识别出来。** |

**这条是全项目的起点**：旧指标下噪声片得分是真实片的 **1.9 倍**，按它优化等于主动劣化。

---

### 7. 评分器基准（n=21）

| | |
|---|---|
| **功能** | 8 条好片 + 13 条坏片（4 类退化 × 3 源片 + 1 真实噪声），跑两套口径对比 |
| **别人怎么做** | 做了个评分器就敢用它做决策，**不知道它准不准** |
| **我们做到** | 给出**准确率、AUC、效应量**三项硬指标 |
| **价值一句话** | **旧口径排序准确率 47.6% ≈ 随机猜测——这句话本身就是发现。修正后 61.9%，AUC 0.625→0.755，Cohen's d 0.557→1.22。** |

**为什么这条最厉害**：它不是说"我们的评分器好"，而是说"**大部分人的评分器可能等于抛硬币，而我们量出来了**"。

---

### 8. 语义打分（Qwen-VL，需 Key）

| | |
|---|---|
| **功能** | 用视觉大模型判断"画面是否符合提示词" |
| **别人怎么做** | 只算像素统计，**不知道画的是不是你要的东西** |
| **我们做到** | 语义分与规则分按 0.6 : 0.4 融合，保留四维口径不变 |
| **价值一句话** | **从"这图清不清晰"升级到"这图是不是你要的"——但这项目前标注为「需 Key」，未并入「已完成」。** |

> 这一项我们**没有吹**：代码就绪，但没用真实 Key 跑过。标注如实。

## 三、选优层（3 项）

### 9. 自动选优（Top1 进 i2v）

| | |
|---|---|
| **功能** | 打完分自动取最高分作首帧，直接进图生视频 |
| **别人怎么做** | 人工在 6 张里挑，挑完还要手动上传 |
| **我们做到** | **点一下"生成候选"，自动出图、自动打分、自动选第一**，选中率实测 1/1 正确 |
| **价值一句话** | **从"生成 → 挑 → 上传 → 生成视频"，压缩成"生成候选 → 生成视频"。** |

---

### 10. 手动改选

| | |
|---|---|
| **功能** | 点任意候选即可覆盖自动结果，记录 `selected_by: user` |
| **别人怎么做** | 自动选错了只能重跑 |
| **我们做到** | **自动给建议，人保留最终决定权**，且记录是谁选的 |
| **价值一句话** | **自动化不夺权——机器排序，人拍板，决策留痕。** |

---

### 11. 比例前置校验

| | |
|---|---|
| **功能** | 首帧比例与目标视频档位不匹配时，提交前直接拒绝 |
| **别人怎么做** | 提交 → 等 25 分钟 → 出来变形/裁切 → 白等 |
| **我们做到** | **秒级返回 `KF_ASPECT_MISMATCH`**，告诉你差 89.7% |
| **价值一句话** | **把 25 分钟的错误，变成 1 秒的错误——这是最便宜的优化。** |

## 四、后处理层（3 项）

### 12. 插帧 30→60fps

| | |
|---|---|
| **功能** | 运动补偿插帧，把 30fps 提到 60fps |
| **别人怎么做** | 要么忍受 30fps 的卡顿感，要么重新生成 |
| **我们做到** | **150 帧 → 297 帧（+147 帧），时长 5.007s 一秒未变，文件反而小 7%** |
| **价值一句话** | **不重生成、不改时长、不增体积，只增加时间采样密度——60 秒处理换 2 倍帧率。** |

---

### 13. RIFE / ffmpeg 双后端

| | |
|---|---|
| **功能** | 有 GPU 权重走 RIFE（画质更好），没有就走 ffmpeg minterpolate |
| **别人怎么做** | 缺依赖就整个功能不可用，或者偷偷降级不告诉你 |
| **我们做到** | **自动降级 + 明确标注** `engine: ffmpeg-minterpolate`、`substitution: 非 RIFE` |
| **价值一句话** | **能力不够时，我们降级但说清楚——而不是假装做到了。** |

---

### 14. 双版本分存

| | |
|---|---|
| **功能** | `native`（原始）+ `enhanced`（处理后）两条记录分开存 |
| **别人怎么做** | 处理后覆盖原文件，**再也回不去** |
| **我们做到** | 两版都在库里，谁的分数更高一目了然 |
| **价值一句话** | **增强是可回溯的实验，不是不可逆的破坏。** |

## 五、工程层（3 项）—— 这一层让"厉害"变成"可信"

### 15. 任务状态机（8 态）

| | |
|---|---|
| **功能** | `queued → submitting → running → postprocessing → succeeded`，异常走 `failed / expired / cancelled` |
| **别人怎么做** | 状态散落在代码里，**任务卡死没人知道** |
| **我们做到** | **64 对转移穷举验证全部一致**，非法转移直接返回 `STATE_INVALID` |
| **价值一句话** | **我们能证明"这个任务不可能卡在中间"——穷举过，不是拍脑袋。** |

---

### 16. 统一错误码 + 负面用例审计

| | |
|---|---|
| **功能** | 12 个错误码 + 54 项自动化审计（含 14 项负面用例） |
| **别人怎么做** | 只测"能通"，错误路径全是 500 |
| **我们做到** | **非法 JSON / 未知路由 / 缺参 / 超大 body / 路径穿越 / 无令牌写接口，全部按预期拒绝** |
| **价值一句话** | **PASS 53 · FAIL 0——我们连"该拒的有没有拒"都测了。** |

> 审计过程中真抓到 12 个 bug，含一个**路径穿越**（`/files/../../etc/passwd` 能读出对象目录外文件）。这条如果没测，就是个安全洞。

---

### 17. 断点恢复

| | |
|---|---|
| **功能** | 关页面、重启进程、后端退出期间任务继续跑，重进自动续接 |
| **别人怎么做** | 关页面 = 任务丢失，25 分钟白等 |
| **我们做到** | 任务 JSON 原子落盘 + `.worker.lock` 防双调度 + `restore()` 重启续接 |
| **价值一句话** | **25 分钟的生成任务，不因为你关了个网页就作废。** |

## 九、一句话总纲

> **别人展示的是"我能生成好看的东西"，这个平台展示的是"我能证明它为什么好看，并且证明我的判断本身没错"。**

前者会随模型迭代贬值，后者不会。
