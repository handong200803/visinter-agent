# 30 · 怎么在本机（8G 显存）稳定出高质量视频

> 结论先给：**纯文生视频是本机最弱的路径。真正让质量跃升的是「首帧驱动」——给模型一张好图，让它只负责运动。**

## 1. 为什么纯文生视频会出「垃圾」

你那条小猫任务的实际输入是：

```
masterpiece, best quality, consistent character, cinematic film still, 35mm, shallow DOF, film grain,
```

主体描述被模板前缀盖掉了（已修）。但这暴露了更根本的问题：

- H3 是 **图/首尾帧驱动** 的模型（`MiniMaxH3ImageToVideo` 的 `first_frame`/`last_frame` 是正式输入），
- 纯 T2V 时它要同时「想象主体 + 构图 + 运动 + 音画对齐」，8G 卡上只能用 640×384 / 20 步，
- 结果就是**拼贴感、重复图案、主体漂移**——不是提示词写得不好，是路径选错了。

## 2. 六条方法（按杠杆从大到小）

### ① 用首帧（杠杆最大，质量差一个档）

```bash
# 先有一张好图（剧照/上一条的某一帧/外部生成的图），然后：
curl -X POST http://127.0.0.1:8418/api/jobs -H "Content-Type: application/json" -d '{
  "engine":"minimax_h3","width":640,"height":384,"output_fps":60,
  "first_frame":"D:/云盘/02-视频/成片/某张剧照.png",
  "values":{"ch.subject":"女孩轻轻转头看向窗外，雨滴沿玻璃滑落","kf.prompt_prefix":"photorealistic, cinematic lighting"},
  "note":"I2V 首帧驱动"
}'
```

原理：模型不再需要「从噪声里长出主体」，只在给定画面上做运动与光影演化。同样 20 步，结构稳定性高一个档。

### ② 提示词写成六要素（不是堆形容词）

```
主体+外观 | 位置/动作 | 光线方向与时间 | 镜头（景别/焦段/景深） | 质感（胶片/颗粒/材质） | 氛围
```

可直接抄的模板：

| 场景 | 模板 |
|---|---|
| 人物 | `一位24岁亚洲女性，黑长直发，米色针织衫，站在落地窗前侧身看雨；午后阴天柔光从左前方入；50mm 浅景深；柯达胶片颗粒；安静克制` |
| 动物 | `一只英国短毛幼猫，银渐层毛色，绿色眼睛，坐在木质窗台上舔爪；侧逆光勾出毛发边缘；85mm 微距浅景深；真实毛发纹理；温暖安静` |
| 风景 | `江南水乡清晨，湿石板路向远处延伸，白墙黑瓦与红灯笼倒映在运河；低饱和自然光；24mm 广角缓慢前推；轻微胶片颗粒` |

负面词（默认已带，可加强）：`模糊, 低质量, 水印, 文字, 畸形手指, 多余肢体, 重复图案, 拼贴, 多个人头, 画面撕裂`

### ③ 分辨率顶到显存上限

| 尺寸 | 像素 | 预估显存 | 本机 8G |
|---|---|---|---|
| 640×384 | 0.25MP | ≈7.2GB | ✅ 稳 |
| **720×480** | **0.35MP** | **≈8.0GB** | ⚠️ 边界可行，慢但能跑 |
| 1280×720 | 0.92MP | ≈12.6GB | ❌ 需 ≥16GB |
| 1920×1080 | 2.07MP | ≈21.8GB | ❌ 需 ≥24GB |

### ④ 采样器必须服从模型（重要）

| 引擎 | sampler | scheduler | steps | CFG |
|---|---|---|---|---|
| MiniMax H3 | **euler** | **simple** | **16–25** | **5–7** |
| Wan2.2 | dpmpp_2m | karras | 16–25 | 7–10 |

**H3 套 DPM++ 2M Karras 会输出整片噪声**（已实测，见 docs/28）。这条是硬约束，不是偏好。

### ⑤ 分镜优于长镜

一条 5s 里塞完整叙事必然崩。改成 **3 条 × 2s**：每条只做一个动作（转头 / 抬手 / 镜头推进），后期拼起来。控制力提升远大于调参。

### ⑥ 60fps 走插帧，别让模型原生出

原生只出 24fps（H3 音画同步固定 24）。60fps 由后处理得到：

```bash
# 需要真 RIFE（严格版要求，不装就明确失败）
set AVP_RIFE=D:\云盘\03-文档\tools\rife\rife-ncnn-vulkan.exe
set AVP_RIFE_MODEL=D:\云盘\03-文档\tools\rife\rife-v4.6
```

没装就保持 24fps——比强行插帧出鬼影好。

## 3. 推荐工作流（本机可行）

```
① 找/生成一张高质量静帧（剧照、外部出图、上一条的满意帧）
        ↓
② I2V：first_frame + 六要素提示词（640×384 或 720×480，euler 20 步 CFG 5–7）
        ↓  约 20–30 分钟
③ 出片 → 看首帧是否守住（抽帧核验）
        ↓
④ 三条 2s 短镜拼接 → 后期（可选 RIFE 60fps）
        ↓
⑤ 归档：_pure.mp4（原生）+ _enhanced.mp4（增强），打分只用 _pure
```

## 4. 出片验收清单（30 秒判断能不能用）

| 检查 | 不合格信号 |
|---|---|
| 首帧是否守住 | 第 1 帧和输入图差异大 → 主体被重绘 |
| 有无重复图案 | 同一张脸/贴片平铺 → 立刻废 |
| 有无噪声 | 整屏纹理（`noise_ratio > 0.9`）→ 采样器错配 |
| 运动是否自然 | 帧间跳变、闪烁 → 降 CFG 或减运动幅度 |
| 音频是否对齐 | 有音轨但和画面无关 → H3 输出正常，注意别二次混音 |

平台已内置自动核验：`server/detail.js` 的退化检测 + `scoring.js` 的 Sbad 硬惩罚（噪声片 F ≤ 0.15）。

## 5. 本机 vs 大显存的分工

| 环节 | 本机 8G | 24G 卡 |
|---|---|---|
| 关键帧图 | 需外部出图 | 可跑本地图像模型 |
| 视频生成 | 640×384 / 720×480，20–30 分钟/条 | 1080p，20 步，10–15 分钟/条 |
| 60fps | 只装 RIFE 才可用 | 同 |
| 批量实验 | 一次一条 | 可并发 2–3 |

## 6. 一句话

**别再让模型从零想象画面。给它一张图，把 20 步全用在「让画面动起来」上——这是 8G 卡上唯一能稳定出好片的做法。**
