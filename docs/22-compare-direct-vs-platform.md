# 22 · 经过平台 vs 不经平台（H3 生成对比，实测）

> 同一台机器（RTX 5060 8G / 16G RAM）、同一 prompt、同尺寸 480×512、同 124 帧、同 4 步 / CFG 1.0。
> prompt：`清晨的江南水乡，湿石板路向前延伸，白墙黑瓦与红灯笼倒映在运河，镜头缓慢前推，低饱和自然光`

## 1. 两条通道定义

| 通道 | 路径 |
|---|---|
| **不经平台** | `node tools/h3_run.mjs`（或 `h3workflow.run`）→ `POST :8188/prompt` → 轮询 `/history` |
| **经过平台** | `POST :8418/api/h3/run` → `jobs(kind=local)` → `comfy provider` → `POST :8188/prompt` → WS/轮询 → 归档 + 索引 |

## 2. 耗时（公平组：不同 seed，均首跑无缓存）

| 通道 | seed | 端到端 | 备注 |
|---|---|---|---|
| 直连 | 901 | **200.4 s** | 1 条 5s 片 |
| 平台 | 902 | **200.3 s** | 1 条 5s 片 |
| 差值 | — | **−0.14 s（−0.07%）** | 纯噪声；平台不增加生成耗时 |

## 3. 缓存命中组（同 seed 777，平台第二条）

| 通道 | 端到端 | 说明 |
|---|---|---|
| 直连（首跑该参数） | 200.6 s | 真算 |
| 平台（同 prompt/seed/参数） | **8.1 s** | ComfyUI `execution_cached` 命中，只重新编码落盘 |

- 结论：**平台不是"更快"，是 ComfyUI 缓存更快**；两条通道都会命中同一个缓存。
- 同 seed 的两次产物：容器字节不同（编码元数据/时间戳），但**首帧像素 md5 完全一致**（`a8204dec…`），即画面内容相同。

## 4. 工程差异（平台真正的价值）

| 维度 | 直连 | 平台 |
|---|---|---|
| 产物落点 | `ComfyUI/output/h3/`（临时区，清缓存即丢） | 复制到 `%CLOUD_ROOT%\02-视频\成片\` + `_index.json` 索引（可搬盘/可检索） |
| 元数据 | 只有文件名 | job 记录：`job_id / providerTaskId / 参数 / 耗时 / workflow / 归档记录` |
| 进度 | 自己写轮询 | SSE `/api/jobs/:id/events` + WS 进度 + 15s history 兜底 |
| 失败处理 | 自己解析 ComfyUI 的嵌套错误 | 统一 `{code,message,hint,detail}`，不自动重投（防重复计费，本地同样防重复跑） |
| 参数校验 | 自己保证 | 帧数 17k+5 / 32 倍数 / 分辨率风险提示（只提示不拦） |
| 可复现 | 保存 workflow JSON | job 里存 `workflow` + `params_digest`，可一键重跑 |
| 作品库 | 无 | 页面「成片作品库」6 条，可播放 / 放大 |

## 5. 平台额外开销拆解（实测口径）

| 项 | 量级 |
|---|---|
| HTTP 转发 + 队列 | < 20 ms |
| job JSON 落盘（~2 KB） | < 10 ms |
| 成片归档复制（2–3 MB） | 50–200 ms（含 EPERM 重试逻辑） |
| 相对 200 s 生成 | **可忽略（<0.1%）** |

## 6. 结论

1. **能不能正常生成**：能。两条通道都出片，480×512/5s/24fps/带 AAC 音轨。
2. **平台会不会拖慢**：不会（差值在噪声内）。慢的永远是 8G 显存 + 16G 内存的权重换入。
3. **平台带来什么**：归档、索引、任务记录、统一错误、进度、可复现、作品库；生成结果与直连**像素级一致**。
4. **什么时候该直连**：只想要一个文件、不关心追溯时。要批量、要复现、要作品库时走平台。
