# 16 · 角色设定自动提取（从提示词回填 ch.* 字段）

> 代码：`server/character.js`（提取器）· `server/recommend.js`（接入 `/api/recommend`）· `server/selftest.js`（12 条断言）
> 定位：**用户写过的才填，没写的留空/留默认**。这一页写清「什么词能识别、识别成什么、识别不了怎么办」。

## 1. 为什么要它

角色设定板块有 42 个 `ch.*` 参数。用户写一句「轮渡上20岁左右女生，格子围巾，深色大衣，侧脸看海，电影感」时，主体、年龄、服装、画风其实都已经说了；再让人逐项手填，是把模型能做的事推回给人。

所以：点「AI 推荐参数」时，除了原有 258 参数推荐，**同时**从提示词提取角色字段并回填；用户改过的字段保留用户的选择，并标「已自定义」。

## 2. 字段映射（对照注册表真实口径，不是理想 schema）

| 字段 | 注册表类型 | 识别规则 | 没写时 |
|---|---|---|---|
| `ch.subject` | text | 取含人物词的第一个短句（无人物则取首句），去掉"电影感/运镜/景深/留白"等技法词 | 留空，不填默认主体 |
| `ch.age` | int | 先认"20岁/23周岁"（取数字，限 3–90）；否则 少年·小孩·男孩·女孩·少女→16，青年·年轻·学生·20出头→24，中年·大叔·阿姨→42，老人·大爷·奶奶→68 | 用注册表默认（24），标 `default`，**不脑补具体岁数** |
| `ch.face_shape` | enum 鹅蛋/圆/方/瓜子/长/心形 | 鹅蛋脸→鹅蛋；瓜子脸·V脸·小V脸·网红脸→瓜子；圆脸·娃娃脸→圆；方脸·国字脸→方；长脸→长；心形脸→心形 | 用当前默认（鹅蛋=平台精致脸口径），不报错 |
| `ch.outfit_1` | text | 服装词库（围巾/大衣/汉服/皮衣/羽绒服…约 40 词）+ 颜色词库（米色/深色/驼色…约 28 词）组合，每件往前找最近的颜色修饰，最多两件 | **留空**，由模型按风格自由发挥 |
| `ch.style` | enum 赛璐璐/厚涂/工笔/水墨/韩漫/日漫/国潮 | 只认**插画**画风词（赛璐璐/厚涂/工笔/水墨/韩漫/日漫/国潮） | 保持默认（厚涂） |
| `ch.consistency` | float 0.5–1.1 | 多镜/分镜/系列/同一个人/保持形象/短剧 → **1.0**；单镜氛围/空镜/剪影/背影 → 0.85；其余 0.85；上限 1.1 | 0.85，标 `default` |

**画风要注意两条线**：`ch.style` 是**插画画风**枚举；「电影感/古风/赛博/暗黑/梦幻」这类是**画面风格**，映射到 cine 七风格 id（`cinema/doc/anime/guofeng/cyber/dark/dream`），由 `/api/recommend` 的 `character.style7` 返回并驱动顶部风格卡片。两者不是同一个字段，谁也不覆盖谁。

## 3. 返回结构（`/api/recommend` → `character`）

```jsonc
{
  "character": {
    "ok": true,
    "subject": "轮渡上20岁左右女生",
    "fields": {
      "ch.subject":   { "value": "轮渡上20岁左右女生", "source": "ai",      "evidence": "提示词主体句…", "confidence": 0.75 },
      "ch.age":       { "value": 20,  "source": "ai", "evidence": "关键词「20岁」→ young", "band": "young" },
      "ch.face_shape":{ "value": "鹅蛋", "source": "default", "evidence": "提示词没写脸型…" },
      "ch.outfit_1":  { "value": "格子围巾，深色大衣", "source": "ai" },
      "ch.style":     { "value": "厚涂", "source": "default" },
      "ch.consistency": { "value": 0.85, "source": "default" }
    },
    "patch": { "ch.subject": "…", "ch.age": 20, "ch.outfit_1": "…" },
    "applied": 3,
    "contradictions": [ { "key": "ch.outfit_1", "from": "黑色皮衣", "to": "汉服", "note": "已按提示词更新" } ],
    "conflicts": [ { "key": "ch.subject", "candidates": ["男孩", "女孩在雪地木屋前"], "reason": "提示词并列出现两个人物" } ],
    "style7": { "id": "cinema", "explicit": true },
    "confidence": 0.5
  }
}
```

- `source` 四态：`ai`（提示词里真有）/ `default`（没写，用默认，**不写值**）/ `empty`（没写且该字段本就该空）/ `conflict`（冲突，等用户点）。
- 前端据此标角标：`ai` → **AI 提取**；用户手动改过的 → **已自定义**；`default`/`empty` → 不弹必填、不标错。

## 4. 交互契约

1. 提示词框 → 点「AI 推荐参数」→ 角色字段一起回填（`patch` 已 coerce，直接落 258 键 `values`）。
2. 已自动填充标「AI提取」；用户改过的标「已自定义」，且**再次推荐不覆盖**用户改过的项（以 `overrides` 集合为准）。
3. 提示词没提到的字段：不强制填、不弹必填警告。
4. 解析冲突（两个人物 / 多人）：`ch.subject` 不进 patch，前端弹候选让用户选，选完才写。
5. 与面板现值矛盾（提示词写汉服、面板是皮衣）：按提示词更新，并提示「已按提示词更新」（`contradictions`）。
6. `ch.style` 与顶部风格卡片双向联动：命中画面风格词时同步卡片；点卡片时覆盖 `style7`，但不动 `ch.style`（插画枚举）。

## 5. Qwen 通路

- 给了 `DASHSCOPE_API_KEY` 时，system prompt 里多了 `character` 可选块（六个键 + 规则），Qwen 返回的 `character` 走 `mergeQwen`：只认六个键，值必须过注册表域校验；越界/坏枚举进 `qwen.rejected[]`（前端可见），**不静默丢弃**、不写进 values。
- 没有 key / 调用失败：纯规则提取，`source:'rules'`，不伪装 AI（沿用既有口径）。

## 6. 已知边界

- 主体提取是**短句级**启发式：它不会做指代消解（"她和她的朋友"只按人物词判冲突），复杂长句可能把场景词一起带进 `ch.subject`；此时 `evidence` 里给的是原文片段，用户可直接改。
- 服装词库是封闭表：库里没有的服装（如"洛丽塔裙撑"）不会被抽出，但 `ch.outfit_1` 留空而不是填错。
- 年龄只做"段位→数字"映射，19 岁与 29 岁在没写数字时都会落到 24，属口径选择而非精度。
- 一致性只按关键词与镜头数判断，不分析提示词的叙事结构。
