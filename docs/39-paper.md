# 当质量指标把噪声判为佳作

**VisInter-Agent · 2026 Qoder 高校创造力大赛**

---

## 一、那天晚上

11 月 20 日，我跑完一条 H3 视频，打开一看，整屏都是雪花点。我以为是参数配错了，就去翻评分器。

它给了 0.6808 分。

比我上午那条还算满意的片子高 0.33。

我又把上午的片子调出来算了一遍：0.3544。

**噪声比真片子高了将近一倍。**

那一刻我意识到的问题不是"我参数调错了"，而是"我用来判断参数对不对的那个东西，可能是错的"。如果我一直按这个分数优化，结果只会越来越差。

这件事之后我做的东西，说到底就是在回答一个问题：**怎么知道自己判断得对不对。**

---

## 二、分数为什么会错

我把评分器拆开看，公式很常规：

```
F = 0.20·Sface + 0.30·Ssharp + 0.25·Sstyle + 0.15·Scomp − 0.10·Sbad
```

Sface 看主体稳不稳，Ssharp 看锐不锐，Sstyle 看风格像不像，Scomp 看构图。四个都是业界常用的代理指标。

问题出在前两个。

**Sface 把"帧间变化小"当成了"稳定"。** 它是用相邻帧的位移估的，变化越小分越高。但视频的稳定应该是"同一个内容在时间上连续"，不是像素不动。一条凝固的画面天然得分高——噪声也凝固不了，但噪声在小尺度上被平均了。

**Ssharp 用的是 Sobel 梯度均值。** 噪声的梯度普遍比干净画面高。所以"噪声锐度高"在数学上完全成立，只是在视觉上是错的。

这两个都不是实现 bug。它们是**代理指标和感知目标本来就没对齐**。写得再仔细也一样。

---

## 三、我加了一层

我没有去调权重。调权重只是把噪声压下去一点，换个场景又会冒出来。

我加了一个独立的判据层，专门判"这是不是一段坏画面"，用 320×180 采样（不降采样，保留高频）算三件事：

| 判据 | 怎么算 | 阈值 |
|---|---|---|
| 噪声比 | 相邻像素平均差 ÷ 块均值标准差 | > 1.15 |
| 边缘密度 | Sobel 二值化边缘占比 | < 0.10（模糊） |
| 块方差 | 8×8 块均值标准差 | < 6（近乎纯色） |

命中任一条，总分直接压到 0.15 以下。

**这里有个我没想到的结果。** 我用 ffmpeg 造了四类退化样本测试，其中一类是"柔和噪声"（`noise=alls=90`）。检测器对它完全没反应，检出率 0%。

一开始我以为是自己写错了，后来把画面调出来看了半天——那类噪声在视觉上真的不明显。**检测器不检出它，是对的。** 如果我强行加个阈值把它抓出来，那只会带来误报。

所以这个检测器的覆盖情况是这样的：

| 退化类型 | 检出率 |
|---|---|
| 真实噪声（采样器错配的产物） | 100% |
| 去色 + 低对比 | 100% |
| 重度模糊 | 33% |
| 人工柔和噪声 | 0%（不该检出） |
| 降采样回放大 | 0%（未覆盖） |

第三行和第五行是我没做好的地方。第三行只抓到了重度，轻度的漏了；第五行需要专门的块边界检测，我没写。

**我保留了这个表，没有把 0% 那两行藏起来。**

## 四、21 条样本

一条样本说明不了什么。我组了个小基准：8 条平时跑出来确认可用的片子，13 条拿它们改的坏片（4 类退化 × 3 个源片 + 1 条真实噪声）。

同一套评分器跑两遍，一遍不开退化检测，一遍开：

| | 好片均分 | 坏片均分 | 坏片压过好片 | 准确率 | AUC | Cohen's d |
|---|---|---|---|---|---|---|
| 不开 | 0.5162 | 0.4285 | 11/13 | 47.6% | 0.625 | 0.557 |
| 开 | 0.4769 | 0.2714 | 8/13 | 61.9% | 0.755 | 1.22 |

第一行那个 **47.6%** 是我看这个表时最在意的数字。13 条坏片里有 11 条压过了至少一条好片，排序准确率和抛硬币差不多。

也就是说，**原来那套指标在"区分好坏"这件事上，基本没有信息量。**

第二行好了一些，但也没有多好。AUC 0.755 是"中等偏强"，不是"完美分类器"。8 条好片里还有 3 条被坏片压着。我没打算说它解决了问题，它只是把信息量从"没有"提到了"有一些"。

效应量从 0.557 到 1.22，是个比较明显的变化：两组分布的重叠少了很多。

## 五、为什么平台里长这些东西

分数准了之后，我才敢拿它做决定。平台里的很多模块，其实都是"因为这个分数不可靠，所以必须多做一步"的产物。

**关键帧出多张，是为了能比。** 只出一张图，分数再准也没有比较对象。所以一次出 3 到 6 张，每张打分排序。自动选第一张进图生视频，但人可以点任意一张改选，记录里会写清是谁选的。机器给建议，人拍板。

**首帧驱动，是为了不让它跑偏。** 纯文生视频每一帧都由模型自由发挥，第三秒主体就变了。把选中的关键帧钉成第一帧，画面才收得住。这两步必须连起来才有意义——没有选优的首帧是随机的，没有首帧的选优是白选的。

**比例不匹配直接拦。** 首帧是 640×832，目标档位是 640×384，差了 89.7%。以前是提交完等 25 分钟，出来一条变形的片子，白等。现在提交前就返回 `KF_ASPECT_MISMATCH`。把 25 分钟的错误变成 1 秒的错误，这大概是我做的最划算的一件事。

**插帧，是因为 30fps 肉眼能看出顿。** 运动补偿插到 60fps，实测 150 帧变 297 帧，时长 5.007 秒一秒没变，文件反而小了 7%，处理 67 秒。我没有重新生成——重新生成要花钱，而且内容会变。插帧只增加时间采样密度，不改内容，所以分数只动了 0.0043，在噪声范围内。

**双后端降级，是因为我拿不到 RIFE 的 ncnn 二进制。** GitHub 那会儿连不上，就从 hf-mirror 下了 PyTorch 版权重，补了两个缺失的模块文件才跑通。在没有 GPU 权重的环境里，就退到 ffmpeg 的 minterpolate。降级这件事我在返回值里写清楚了：`engine: ffmpeg-minterpolate`，`substitution: 非 RIFE`。**能力不够的时候降级，但不能假装没降。**

**双版本分存，是因为增强不可逆。** 处理后覆盖原文件，就再也回不去，也说不清分数变化是增强带来的还是别的。原始版叫 `native`，处理后叫 `enhanced`，两条记录都在库里。

## 六、那些不出现在画面里的东西

上面这些是评委能看见的。还有一层看不见的，但我觉得更值得说。

**状态机。** 任务从排到跑到完成，中间有 8 个状态。我把它写成一张转移表，然后把 8×8 共 64 对全跑了一遍，确认每一对都符合设计。写完这个测试，我才敢说"这个任务不会卡在中间"。这不是拍脑袋说的，是穷举过的。

**错误码审计。** 我写了个脚本，跑 54 项检查，其中 14 项是"该拒绝的有没有拒绝"：非法 JSON、未知路由、缺参数、超大请求体、无令牌写管理接口。

这个脚本抓到了 12 个真 bug。最严重的一个是**路径穿越**——`/files/../../etc/passwd` 能读出对象目录外面的文件。这个如果不测，就是个安全洞。

还有两个挺低级的：我把万相的异步生图当成同步写了，接上去以后关键帧永远拿不到 URL，静默失败；后处理把相对路径直接喂给 `fetch`，每次都报 `Failed to parse URL`。

**断点恢复。** 一条片子跑 25 分钟，关个网页就没了，这体验说不过去。所以任务一创建就原子写盘，进程重启后能续接，后端退出期间 ComfyUI 跑完的也能在重启时取回。

这些东西没有一个能让画面变好看。但如果没有它们，前面那些"能看见的东西"随时会塌。

## 七、它不是什么

写到这里得说清楚边界，不然容易误读。

**它不是一个能替代剪映的工具。** 功能很窄，性能受本机 8G 显存限制，1080p 只能走云端 API。

**它没有自己的模型。** H3、Wan2.2、万相全是第三方的。我做的是编排和评估，不是生成。

**它不是一个通用的质量评估标准。** 21 条样本撑不起"标准"这两个字。我只能说"在这批样本上有效"，换个模型、换个题材可能就不一样。

**它也没有全自动。** 关键帧选区、参数选择、要不要增强，仍然需要人做判断。

那它是什么：**一个把"这段视频到底好不好"从主观判断变成可复现实验的东西，附带一个真实的失效案例和一次修正。**

## 八、评委可以怎么用

不用听我说，三条命令：

```bash
git clone https://github.com/handong200803/visinter-agent
cd visinter-agent

# 跑评分器基准（第三节那张表的数字）
node tools/scorer_bench.mjs

# 跑 54 项审计
node cloud/audit.mjs --base http://你的后端 --admin <TOKEN>

# 跑平台门禁
node tools/selftest_all.mjs
```

**跑出来的数应该和上面一致。如果不一致，说明我错了，这个作品的结论就不成立。**

我把"能被证伪"当成设计的一部分。没有一条结论依赖我的话，全部依赖这几条命令。

在线版还有一步可以亲手做：打开站点，找到「⑥ 在线全功能」，填提示词，出片，点「增强 60fps」。你会看到任务 ID、耗时、分辨率和入库记录。花不到两块钱。

## 九、没做完的

| 问题 | 现状 |
|---|---|
| 样本少 | 21 条，好片只有 8 条，统计上不够 |
| 没算显著性 | 没跑 p 值和置信区间，只给了效应量 |
| 语义维度缺失 | Sstyle 现在是颜色词规则匹配，接了 Qwen-VL 但没 Key 实测 |
| 模糊和块状漏检 | 33% 和 0% |
| 分辨率上不去 | 本机 8G，只能 640×384 |

这些我写在这里，不是为了显得坦诚，是因为它们真的会影响结论的强度。**一个 AUC 0.755 的评分器，不能拿来当"质量保证"用。**
