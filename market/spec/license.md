# 模板授权条款（`license` 字段的可执行定义）

> 这份文件不是法律意见书，是**结算与审核同学照着就能判的执行口径**。
> 每条条款都对应一个可检查的字段或可复算的公式；判不了的东西不写进来。
> 适用对象：`market/spec/template.schema.json` 里 `license` 取值 `free | paid | revenue_share` 的 `.avptpl` 模板。

---

## 0. 三条硬规则（先立规矩，再看细则）

| 编号 | 规则 | 检查方式 |
|---|---|---|
| R1 | `license` 与 `pricing.mode` 必须一致，否则包不可上架 | `pack.verify` → `pricing_mode_mismatch` |
| R2 | `free` 价格必须为 0；`paid` 必须 >0；`revenue_share` 分成比例之和必须 = 100 | `verify` → `free_must_be_zero` / `paid_must_cost` / `bad_share` |
| R3 | 质量分 < 60 的模板只能挂 `free`（基价档 `draft` = 0） | `pack.suggestPrice` 纯函数，可复算 |

质量分来源：`core/engine.js` 的 `estimate().quality.score`（38–99）。它由参数的实际取值决定，**不能手填**，所以"值不值这个价"和"卖多少钱"是同一条链上的两个端点。

---

## 1. `free` —— 免费，可再分发

| 维度 | 口径 |
|---|---|
| 允许 | 任何人下载、安装、在本机任何项目里使用；可原样再分发（网盘/群/仓库），不必署名 |
| 禁止 | 把 `free` 包改成原作者的 `paid`/分成包出售；移除 `author`/`lineage` 后冒充原创上架 |
| 二次创作 | 允许，且必须保留 `lineage.derived_from` 指向原 id。派生包可以自己定价（此时派生包不再是 free，见 §4） |
| 商用边界 | 商用无限制：接商单、投广告、卖成片都行，不收钱、不分账 |
| 分成口径 | 无。`pricing = {mode:"free", price_cny:0}`，不写 `share` |
| 平台侧 | 只做完整性校验（checksum + 签名）；不承担质量赔付 |

## 2. `paid` —— 一次性买断

| 维度 | 口径 |
|---|---|
| 允许 | 购买方无限期、无限次在本方设备上使用；用于自己接的商单 |
| 禁止 | 转售、转赠、共享账号式分发；把包内 `values` 整段导出成新包再上架（等于绕过买断） |
| 二次创作 | 允许改参数、改配色、改风格做成**自己的派生模板**，但该派生包必须保留 `lineage.derived_from`，且**不得再以 `paid` 原价出售**（见 §4 派生定价） |
| 商用边界 | 买断即含商用（成片可商用）；**不含**把模板本身作为商品/赠品二次流通 |
| 分成口径 | 无分成。`share` 字段必须缺省 |
| 退款 | 交付后 7 天内、且未产生派生包，可全额退；退款后授权即失效（本地记录的 `order_id` 置为 revoked） |

`paid` 的价格不是作者随便填，取 §5 规则表算出的建议值，允许上下浮动一档：

| 质量分档 | 基价 | 允许区间 |
|---|---|---|
| `basic` 60–69 | ¥8 | 6–12 |
| `pro` 70–79 | ¥18 | 12–26 |
| `plus` 80–89 | ¥32 | 24–45 |
| `flagship` 90–99 | ¥48 | 36–199 |

超出区间需写 `pricing.note` 说明理由（审核人工过）。这样做是为了防止两种坏情况：把 60 分包标 199（骗一次就走），把 90 分包标 1 元（刷榜挤掉正常作者）。

## 3. `revenue_share` —— 分成

| 维度 | 口径 |
|---|---|
| 允许 | 前端低价甚至 0 元获客，作者从后续流水持续拿钱；适合"教程/系列/持续更新"型模板 |
| 禁止 | 用分成模式上架**一次性交付、后续零维护**的包（分成的前提是持续交付，不是套壳白嫖渠道） |
| 二次创作 | 同 `paid`，且派生包的分成关系按 §4 继承份额 |
| 商用边界 | 买家用成片商用不额外收费；模板本体仍不得转售 |
| 分成口径 | `pricing = {mode:"revenue_share", price_cny:前置价, share:{creator_pct:60, platform_pct:40}, basis:"净流水（扣除支付通道费与税费后的实收）"}` |

结算公式（**可复算**，审核与作者用同一套）：

```
净流水      = 订单实收 − 支付通道费(3%) − 税费(按发票口径)
作者可得    = 净流水 × creator_pct/100 + 前置价 × 100%      # 前置价全额归作者
平台可得    = 净流水 × platform_pct/100 − 前置价            # 前置价由平台先行垫付渠道成本
起结门槛    = 单次结算 ≥ ¥50；不足则滚入下一期（防小额转账成本吃掉收益）
结算周期    = 自然月，次月 10 日出账，15 日打款
```

边界条款：

- `creator_pct + platform_pct` 必须 = 100，否则包直接拒收（`bad_share`）。
- 前置价 = 同档 `paid` 价 × 0.6（`PRICE_ADJ.revenue_share_factor`），四舍五入取整。理由：分成模式下渠道成本已由平台垫付，前置价不该按买断价收。
- 退款订单：净流水按 0 计，前置价原路退回作者额度（因为货已交付，平台承担退款成本）。
- 结算基数只认**平台内订单**。作者私下交易、把包挂到别的渠道卖，不在分成范围，也不受本条款保护。

## 4. 派生模板（三种模式共用）

| 情形 | 规则 |
|---|---|
| 从 `free` 派生 | 派生包可自行定价；须在 `lineage.derived_from` 写明原 id |
| 从 `paid` 派生 | 派生包可卖，但价格上限 = 原包价格（防止"抄一遍再卖更贵"） |
| 从 `revenue_share` 派生 | 派生包流水的 `creator_pct` 里，**30% 归原包作者**，剩余 70% 归派生作者；平台侧不变 |
| 派生链深度 | `derived_from` 只记直接父级；结算时按链上溯，每层最多抽 30%，累计不超过 45% |
| 抄袭判定 | 派生包与父包 `values` 完全相同（checksum 相等）视为**转载**，不算派生，按父包的授权模式处理 |

## 5. 定价规则表（`PRICE_ADJ`，与 `market/pack.js` 一一对应）

| 项 | 值 | 理由 |
|---|---|---|
| 档位基价 | draft 0 / basic 8 / pro 18 / plus 32 / flagship 48 | 贴着质量分刻度，默认参数约 78 分（`pro`） |
| 每多覆盖 1 个板块 | +¥2 | 覆盖板块数 = 作者实际工作量，第 1 个板块不计 |
| 交付 4K | +¥4 | 4K 要走超分链，时间成本可测 |
| 分成模式折价系数 | ×0.6 | 见 §3 前置价说明 |
| 天花板 | ¥199 | 单人模板超过 200 平台不背书 |
| 地板 | ¥0 | 低于 60 分强制 free |

计算示例（可直接用 `node tools/tpl.mjs verify <file>` 复核）：
「商业产品转台」质量分 84 → `plus` 基价 32，覆盖 3 个板块 +4，交付 4K +4 → **¥40**。

## 6. 违约与下架（可执行动作，不是口号）

| 行为 | 处理 |
|---|---|
| checksum 与作者声称不符 | 自动下架；已购用户可保留本地副本（货已交付），不再分发 |
| 签名缺失 | 允许上架但标"未验签"，不进入首页推荐位 |
| 分成包 6 个月零更新且零流水分成 | 转为 `paid` 存量授权（老用户不受影响），避免长期占位 |
| 一次买断包被检出转售 | 撤销该 `order_id` 授权并公示；作者不受影响 |
| 抄袭判定成立（见 §4） | 派生包下架，流水按原包模式重算 |

---

## 7. 签名与它不能保证的事

`market/sign.js` 提供 HMAC-SHA256 完整性签名，用于回答"这个包从作者发出后有没有被改过、是不是同一个作者发的"。它**不提供**：

- 版权保护或内容加密（`.avptpl` 是明文 JSON，这是刻意的取舍：可 diff > 防拷贝）；
- 防逆向（参数值本身就在文件里，读到就能抄）；
- 授权控制（不装 DRM、不做在线激活）。

真正约束交易的是本文件的条款与结算流水，而不是密码学。**任何宣称"签名即防盗版"的话术都不成立，市场页不得这样写。**
